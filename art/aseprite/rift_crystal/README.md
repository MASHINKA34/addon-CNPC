# Кристалл разреза

Четыре шкуры `amethyst`, `ember`, `void`, `ice` для одной GeckoLib-модели.
Модель и анимации созданы через **Blockbench MCP** в формате `geckolib_model`
(Blockbench 5.1.6, установленный плагин GeckoLib Models & Animations).
Пиксель-арт, слоистые исходники и превью собраны **Python + Pillow + NumPy**.
**Aseprite MCP** использован для независимого открытия и экспорта исходников:
пиксели всех четырёх экспортов совпали с runtime PNG.

## Файлы и пересборка

Из корня репозитория, Python 3 с Pillow и NumPy:

```sh
python scripts/generate_rift_crystal_skins.py
python scripts/generate_rift_crystal_skins.py --check
```

Первая команда пересобирает четыре PNG, `.aseprite`, `.gpl` и пять листов
превью. Вторая ничего не пишет: проверяет побайтовую воспроизводимость и
технический контракт. Проверено с Pillow 12.3.0 и NumPy 2.5.2.
Цвета и рисунок правятся в скрипте. `.aseprite` также можно редактировать
вручную, но следующая генерация заменит эти ручные изменения.

Модель: `art/blockbench/rift_crystal/rift_crystal.bbmodel`. В проект встроены
все четыре PNG; на каждом кубе отдельно выполнен `apply_texture`, исходно
назначен аметист. Встроенные изображения позволяют открыть проект на другой
машине, даже если сохранённый путь к внешней текстуре недоступен.
Геометрия экспортирована из этого проекта кодеком Blockbench `bedrock`:

- `src/main/resources/assets/cnpcgeckoaddon/geo/rift_crystal.geo.json`
- `src/main/resources/assets/cnpcgeckoaddon/animations/rift_crystal.animation.json`
- `src/main/resources/assets/cnpcgeckoaddon/textures/entity/rift_crystal/<style>.png`

При изменении модели: сохранить `.bbmodel`, экспортировать геометрию через
GeckoLib / Bedrock, затем запустить:

```sh
python scripts/generate_rift_crystal_skins.py --normalize-animation
```

Анимация первоначально экспортирована кодеком `Format.animation_codec.compileFile`.
Blockbench 5 оборачивает числовые ключи в `vector`; нормализация записывает
те же линейные ключи из `.bbmodel` обычными массивами GeckoLib 4 / JSON 1.8.0.
Она сохраняет время, направление вращения и преобразование координат Blockbench.
После пересборки обновить четыре текстуры в Blockbench и сохранить проект;
`--check` сверяет встроенные PNG с итоговыми текстурами. Геометрию скрипт не
меняет: её кубы, UV и пивоты сверяются с настоящим экспортом проекта.

## Геометрия, UV и движение

11 кубов, габариты в позе покоя **10,409 × 22 × 10,409** юнита. Минимум Y = 0.
Радиус в плоскости XZ меньше 6, поэтому поворот также укладывается в ширину 12.
Корень `crystal`, пивот `[0, 0, 0]`; непосредственные дети — `core`, `shards`.
У `shards` четыре дочерние кости `shard_north`, `shard_east`, `shard_south`,
`shard_west`: они нужны для настоящего разлёта в разные стороны. Локальные
смещения кости задаются относительно её родителя; четыре направления явно
различаются. Перед по контракту −Z; выделенного рисунком лица нет.

Одна UV-развёртка 64×64: 66 отдельных граней без наложений, с промежутками.
Исходники имеют слои `facets`, `edges`, `core_and_marks` и выключенный,
заблокированный `UV_template_hidden` с границами всех островов. Видимые
слои объединяются в RGBA8; внутри каждой грани альфа 255, снаружи 0.

- `idle`: 4 секунды, loop. Y: 0 → 360° с равномерной скоростью 90°/с;
  высота: 0 → +1,5 → 0 → −1,5 → 0; масштаб ядра 0,9 ↔ 1,1.
- `collect`: 0,5 секунды, один раз. В первые 0,15 с масштаб 1 → 1,4;
  затем каждый осколок отходит на 4 локальных юнита (5,6 с масштабом
  корня), `shards` поднимается на 5, ядро сжимается до 0,05.
  Исчезновение всей сущности после 10 тиков выполняет код промта 93.

## Палитры и художественные решения

На каждую шкуру — ровно 14 непрозрачных цветов, встроенная палитра Aseprite
и отдельная `.gpl`. Свет создаётся цветом, без полупрозрачности, свечения
фильтрами, градиентов или сглаживания. Светлое ребро шириной 1 px,
крупные цветовые плоскости и более светлое ядро читаются при вращении.

- `amethyst`: ванильный аметист как цветовой ориентир; сине-фиолетовые тени,
  розово-сиреневые грани и почти белое ядро.
- `ember`: сверена `art/boss_bar_infernal/infernal_fire.gpl`, но фактический
  файл содержит 32 почти чёрных оттенка, без огненных цветов. Взята угольная
  опора `#171717`, добавлены сливовые тени, красно-оранжевые грани и жёлтое
  ядро по описанию задачи. Это осознанное расхождение с палитрой-ориентиром.
- `void`: ориентир — `art/aseprite/boss_bar/sculk/build_runtime_layers.lua`;
  сохранены `#0d141c` и `#088591`, остальные тона подняты по яркости для
  умножения цветом из настроек. Редкие зелёные искры и зелёное ядро.
- `ice`: ориентиры — ванильный лёд и снег; сине-сиреневые тени,
  бледно-голубые грани, белые блики, голубое ядро.

## Проверка и просмотр

`preview/<style>_4x.png` и `preview/all_rift_crystal_4x.png` показывают
геометрию из `.bbmodel` с фактической текстурой: три ракурса на тёмном фоне,
условную площадку в цветах эндерняка/обсидиана, четвёртый ракурс и UV на
светлом фоне, палитру и размерные пробы 10/20 блоков. Все листы увеличены
ровно ×4 nearest neighbour. Пробы рассчитаны для вертикального FOV 70° и
высоты окна 240 px, затем увеличены вместе с листом; это **не игровой тест**.
`preview/model.png` — настоящий скриншот приложения Blockbench через MCP.

Автопроверка: размер, RGBA8, 14 цветов, отсутствие semi-alpha, непрозрачность
внутри UV, отсутствие пересечений, совпадение каждой грани/куба с экспортом,
иерархия костей, повернутые габариты, радиус вращения, ключи и длительности
обоих клипов, направления разлёта, встроенные текстуры и воспроизводимость.
Дополнительно проверены кадры анимации в Blockbench и экспорт четырёх
исходников штатным Aseprite. `gradlew.bat build` проходит. Первый запуск
столкнулся с записью другого Gradle-процесса в общий `build/classes`;
повторный запуск завершился успешно без правок Java или настроек сборки.

В игре после подключения кода промта 93: открыть настройки кристаллов
разреза, выбрать `riftCrystalLook = 1`, `riftCrystalSkin = amethyst | ember |
void | ice`. Для исходной палитры — белый `riftCrystalColor`, для полной
яркости — `riftCrystalGlow = true`. Проверить вращение, покачивание, сбор,
разные цвета умножения и чтение силуэта с 10–20 блоков. Этот арт-пакет не
меняет Java, локализацию, регистрации или `mod_version`; игровой прогон
интеграции остаётся человеку. На доске ставится «Сделано», не «Проверено».
