# Third donor batch model import report

Four donors, one section each, imported on 2026-09-16 with `scripts/import_round3_resources.py`,
`scripts/convert_round3_java_models.py`, and `scripts/ensure_round3_animations.py`. The
inventory of all four archives is `scripts/inventory_round3.json`. No class files, manifests,
registries, data packs, sounds, recipes, language files, or block, item, armor, and screen art
were imported from any of them, and none of the donors is a runtime dependency.

## 01 EEEAB's Mobs

### Source and scope

- Source: CurseForge project `eeeabs-mobs` ("EEEAB's Mobs"), project id 921600, file id 8073814,
  version `1.20.1-0.98.1` (beta, uploaded 2026-05-11), the newest file tagged both `1.20.1` and
  `Forge` in the cfwidget metadata.
- Donor archive: `D:\GEYDEV\donor_mods_round3\01_eeeabs_mobs.jar` (`eeeabsmobs-1.20.1-0.98.1.jar`,
  29,425,926 bytes, size verified against cfwidget).
- SHA-512: `6f3335b4c1f2442ae7233f4c6dc128ac3502b1997b859fce191fe887b4ff71371689b404e5a3e278eea47ab5ffe08d263c80d1e4c2e690cd30d6b1e6175187e1`.
- Donor platform: Forge 1.20.1. The donor code is not loaded or packaged.
- License: `license = "LGPL-3.0"` in `META-INF/mods.toml`; the CurseForge project metadata exposes
  no license field and the jar carries no license file. Author: EEEAB (the only listed member).
- Destination namespace: `eeeabsmobs` (the donor's own namespace, no collision with the 39
  namespaces already in the bundle, so no remap was needed).

The inventory found no `.geo.json` and no animation JSON at all: every creature is a Java
`ModelPart` model (`com.eeeab.eeeabsmobs.client.model.entity`) built from a vanilla
`LayerDefinition`, animated by the mod's own copy of the keyframe classes
(`com.eeeab.animate.client.animation.AnimationDefinition`, readable names) plus procedural
sine motion and static rest poses in `setupAnim`. `convert_round3_java_models.py` reads the
`LayerDefinition` of the layer each renderer registers (`ModelCorpse` has two: the corpse and the
villager corpse), converts cubes, pivots, UVs, and mirroring to GeckoLib geometry, bakes the
unconditional `setStaticRotationAngle` calls into the bone rotations (GeckoLib adds keyframes to
the geometry pose exactly the way the donor adds them to the static pose), and converts every
authored clip the model plays in `setupAnim`. Portable idle, walk, and attack loops from the
round-two converter stand in for the procedural motion; authored clips of the same name win.

sage, and passive variants) and the generator's renderer scan keeps the last class it meets.
These pairs are pinned in `scripts/generate_mob_texture_mappings.py` to the base entity's own
default sheet: `armored_cyclops` -> `armoredcyclopstexture.png`, `baby_saurian` ->
`babysaurian.png`, `chimera` and `chimera_passive` -> `chimeratexture.png`, `gargoyle` ->
`gargoyletexture.png`, `goblin` -> `goblingtexture.png`, `harpy` -> `harpytexture.png`, `saurian`
-> `sauriantexturefixteeth.png`, and `goat` and `snake` -> `chimeratexture.png` (they are the
chimera's heads and share its atlas). Every other pair comes from the donor's own
`getTextureResource` and entity texture default. The brown, gore, snow, armored, and hellhound
variant sheets are bundled and can be picked by hand.
