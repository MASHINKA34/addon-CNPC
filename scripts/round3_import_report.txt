# Third donor batch model import report

Four donors, one section each, imported on 2026-09-16 with `scripts/import_round3_resources.py`,
`scripts/convert_round3_java_models.py`, and `scripts/ensure_round3_animations.py`. The
inventory of all four archives is `scripts/inventory_round3.json`. No class files, manifests,
registries, data packs, sounds, recipes, language files, or block, item, armor, and screen art
were imported from any of them, and none of the donors is a runtime dependency.

Animation policy (reworked on 2026-09-16 after review; every count and table below comes from a
full rerun of the pipeline): the converter writes a portable idle, walk, or attack loop only for
an action the donor has no authored clip for, reads the `<holder>_` prefix of MCreator clip names
from the clips themselves, and leaves out a placeholder that would move no bone (except `idle`,
which every model must carry); `ensure_round3_animations.py` then aliases `idle`, `walk`, and
`attack` to the donor's own clips and replaces a static `idle` with a clip that moves whenever
the model has one. In the tables, `static` marks a clip that exists but moves no bone.

The inventory found no `.geo.json` and no animation JSON at all: every creature is a Java
`ModelPart` model (`com.eeeab.eeeabsmobs.client.model.entity`) built from a vanilla
`LayerDefinition`, animated by the mod's own copy of the keyframe classes
(`com.eeeab.animate.client.animation.AnimationDefinition`, readable names) plus procedural
sine motion and static rest poses in `setupAnim`. `convert_round3_java_models.py` reads the
`LayerDefinition` of the layer each renderer registers (`ModelCorpse` has two: the corpse and the
villager corpse), converts cubes, pivots, UVs, and mirroring to GeckoLib geometry, bakes the
unconditional `setStaticRotationAngle` calls into the bone rotations (GeckoLib adds keyframes to
the geometry pose exactly the way the donor adds them to the static pose), and converts every
authored clip the model plays in `setupAnim`. Portable idle, walk, and attack loops from the
round-two converter stand in for the procedural motion only where the model has no authored
clip of that action; where the donor names it differently (`attack_1`, `attack_left`,
`punch_left_1`, `melee1`, `elbow_strike`, `slash`, `smash`), `ensure_round3_animations.py`
aliases the standard name to it.

The inventory found no `.geo.json` and no animation JSON: all 85 model classes are MCreator Java
`ModelPart` models (`client/model/Model*.java`, SRG names) with vanilla `AnimationDefinition`
holders (`client/model/animations/*Animation.java`). `convert_round3_java_models.py` converts the

`castbeast_`, `aod_`, `storm_`, and so on), and adds the portable loops only for the actions the
donor has no authored clip for. Each identifier is named after the
entity the renderer serves (`Modelaodre` -> `java_armor_of_desert`, `Modelunknown` ->
`java_icefairy`, `Modellichnogeo` -> `java_lich`, and so on).
